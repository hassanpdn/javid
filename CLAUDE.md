# Javid school AI demo

Demo of AI assistants, listed as cards after the live site's door: an elementary school (the main one, described below) and a fabric wholesaler (`fabric/`, see its section). For the school, the default is Javid non-profit elementary school (مدرسه غیرانتفاعی جاوید), Tehran; the first screen is a setup form where the demo is set up for any school (name, boys or girls, city, district, manager, counselor and staff names). Every role has its own login and panel. All data is fake and generated by `seed.py`.

## Run

```
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # then edit
python seed.py                # wipes and rebuilds school.db with demo data
python ingest.py              # chunks docs/ into the Chroma vector db (./db)
uvicorn app:app --reload      # http://localhost:8000
```
Frontend (Node 20.19+, pnpm), only needed when changing the UI:
```
cd frontend && pnpm install
pnpm dev                      # http://localhost:5173, hot reload, API calls proxied to :8000
pnpm build                    # writes the finished site into ../static (committed, so the demo needs no Node)
```
Tests (no Ollama needed: a fake model in `tests/fake_llm.py` stands in, and can misbehave on purpose):
```
pip install -r requirements-dev.txt
pytest                                        # API, privacy, checks, validation, dates, concurrency
cd frontend && pnpm exec playwright install chromium   # once
PYTHON=../.venv/bin/python pnpm test:e2e      # browser tests for every role
```
The demo follows the real date: `seed.py` builds everything around today, and the server rebuilds the data on startup when it was made on another day. `DEMO_TODAY` pins a date, `KEEP_DB=1` keeps old data. The school's details live in `school.json` (per machine, not committed; `SCHOOL_PATH` moves it). It holds only the school being shown: the demo is given to different schools, so no school may ever see another school's name (no saved list, nothing named on the setup form, Javid's details only behind «تنظیمات پیش‌فرض»). Without the file the app opens on the setup form and `GET /school` gives nothing out. Only Hassan runs the demos, so the setup form has no password. Runtime role switches (`POST /features`, «چه کسانی وارد شوند» on the login page and in the setup's last step) turn the parent and student roles off at once, without rebuilding data: with both off the app is an internal CRM for the school staff. Server side, `school.role_enabled` blocks login and ends sessions of switched-off roles (`auth.current_user`), parents drop out of referral recipients, and counselor messages to parents return 403. On the live server two more switches are on, both off by default (local runs and tests): `SITE_USER`/`SITE_PASSWORD` turn on the site's door (`gate.py`, `GatePage.vue`): every API call except `/gate/*` returns 401 `{"detail":"site"}` until the browser has the door's signed cookie (30 days); the password lives only in the server's `.env`, never in the repo. `ADMIN_USER`/`ADMIN_PASSWORD` turn on a login for each assistant (`access.py`, `lib/access.js`): the permanent account (checked first at the door too, so one login opens everything) sees every card and «دسترسی‌ها» below them (`AccessManager.vue`, `AccessForm.vue`), where it gives people accounts: name, username, password, one or more assistants, an optional expiry date and time (Jalali «1405/08/30 18:30», picked with `core/DatePicker` and `core/TimePicker`, empty = no expiry; «today» comes from the server's clock in Tehran, `GET /access/status`, never the visitor's computer). Anyone else sees only their own cards (full access inside); someone through the door without an account gets a login box (`AccessDialog.vue`). Changes apply on the next call; a new password, deletion or the expiry passing end their logins. The API answers 401 `{"detail":"access","app":...}` otherwise. Accounts live in `access.db` (`ACCESS_DB_PATH`), which resets and reseeding keep. `RESET_ON_LOAD=1` makes every page load call `POST /setup/reset` (forgets the school, logs everyone out), so each visit starts on an empty setup form; without it the endpoint is 404. Other settings: `SHOW_DOCS=1` turns on /docs, `ALLOWED_ORIGINS` allows other sites to call the API, `SESSION_DAYS` (default 7).
Models run in Ollama on the Mac: `qwen3-14b` (chat) and `bge-m3` (embeddings), both through the OpenAI-compatible API. Python 3.15 breaks chromadb builds; use 3.12. Demo users all have password `1234` (modir, edari, moalem, karimi, moshaver, vali, daneshamooz, plus teacher{id} and parent{student_id}).

## Layout

- `app.py`: FastAPI app, login, `/chat` (document Q&A), includes all routers. Static files are mounted last.
- `school.py`: the school this demo is for (default Javid) and every name built from it (`full_name`, `signature`, `education_office`, `manager`, `counselor`). `GET /school`, `GET /setup/default` and `POST /setup` in `app.py`; setup rebuilds the demo data and clears the model caches.
- `checks.py`: every check on model output (whole-number matching, per-grade stats lines, date+time pairs, attendance labels, parent-safety: no diagnosis, comparison, private notes or other children). Model text that fails is replaced by text built in code.
- `common.py` normalize/embed/collection, `ingest.py` per-article chunking with `access_{role}` metadata, `llm.py` `ask_llm` / `ask_json`.
- `db.py` SQLite schema and helpers (`notify`, `users_with`, `stamp`), `seed.py` demo data with planted scenarios.
- Role routers: `manager.py`, `staff.py` (letter agent), `counselor.py`, `parent.py`, `parent_chat.py` (parent asks about own child), `notifications.py`.
- `students.py` per-student facts and signal rules, `stats.py`, `jalali.py` date conversion.
- `frontend/`: Vue 3 + Vite + Tailwind 4 + GSAP. `src/pages/` one panel per role plus `GatePage` (the live site's door «Pudineh Agent Center», in English and left to right, not about any one field) and `HubPage` (after the door: every assistant as a card, today only the school one; `TimePicker`: v-model «18:30», 5-minute steps, nothing before `min`; both look like a plain input, share `picker.css` and `lib/popover.js`, take colours from the theme tokens or `--dp-*`, and use only `dp-`-prefixed class names because `main.css` has global ones like `.empty`; `BrandMark`: the Pudineh mark in currentColor, the same shape as `public/favicon.svg`; put new general-purpose pieces here), `src/components/` shared pieces (`SchoolCard` the live school card next to the setup steps, `AppLayout` sidebar/navbar/dark mode, `FloatingChat` the assistant button in the bottom-right corner of every role, `ChatBox`, `NotificationBell`, charts, the manager's `ManagerLetters` page and `AttendanceDrawer` / `TeacherLatesDrawer` / `ManagerStudent` drawers; the manager's student file has no counselor notes or health forms), `Skeleton` placeholders shaped like the content that is loading, `ToastHost` and `ActivityPill` (toasts and the navbar pill for background work, store in `src/lib/notify.js`); phones (`src/lib/viewport.js`, under 768px) get a bottom tab bar from `AppLayout` (the panel's pages, the assistant in the middle, notifications, an account sheet) instead of the sidebar and the round assistant button, and dialogs and drawers open as sheets from the bottom that close by pulling down (`v-pop`/`v-drawer`), `src/lib/` (`api.js` session and fetch, `jalali.js` Jalali dates in the browser, `school.js` the school's details for every page, `chat.js` opens the floating assistant, `motion.js` GSAP directives `v-reveal`/`v-pop`/`v-drawer`, `theme.js`, `icons.js`, `constants.js`), `src/styles/main.css` design tokens (light/dark) and components. ## The fabric wholesaler (`fabric/`, `frontend/src/fabric/`)

A Tehran fabric wholesaler (عمده‌فروشی پارچه) with customers all over Iran, who works with three Excel files and the phone. Everything is simulated and Hassan has said not to ask before choosing details: real customers will change it anyway.
- Its own everything: settings in `fabric.json` (`FABRIC_PATH`), database `fabric.db` (`FABRIC_DB_PATH`), the three workbooks in `fabric_files/` (`FABRIC_DIR`), logins `sahebkar` (owner), `forooshande` (seller), `hesabdar` (accountant), password `1234`. A school token never works on `/fabric/...` and the other way round; the frontend keeps `fabricSession` beside `session` (`lib/api.js` picks the token by path).
- `excel.py` builds four months of business into انبار/فروش/حسابداری.xlsx (with planted situations: a bounced cheque from the biggest buyer, a customer over his credit limit, a fabric about three days from running out, dead stock, next week's cheques not covered, a regular customer gone quiet), then reads them back like a stranger's files: names written several ways, Persian digits, a hand-typed total row; each fix becomes an import note shown in the panels. A sale confirmed at the phone desk is written into all three files.
- `facts.py` computes every number; money is always worded by `money()` (e.g. «۱۲۸ میلیون تومان») so model text can be checked with `checks.only_known_numbers`. Model text that fails, or no model answer, falls back to text built in code (`_written` in `api.py`).
- The wholesaler had a theft, so the demo is built around trust: `facts.reconcile()` checks the three files against each other (stock: opening + deliveries − sold = on the shelf; invoice numbers without gaps; each day's cash sales = that day's deposit in «صندوق»; every cheque sale has its cheque). `PLANTED` leaves the marks a theft leaves (an invoice removed from the sales file whose fabric still left the warehouse, one evening's cash short) and the checks find them from numbers alone. Findings say what does not add up and show the sum, never who did it. Every number on the owner's dashboard and in reports has «از کجا؟» (`HowTip`) with the sum and the sheet each part comes from. Every change goes into `events` with who and when (`store.log`); the owner sees it live («همین حالا») and in «تطبیق». The seller does not see checks or the log.
- «سایت فروشگاه» (`shop.py`, `ShopView.vue`): the shop's website as an end customer sees it, with an assistant that takes orders in short sentences, asks only what it needs (which colour, how many rolls, a mobile number; a known number is recognised) and gives an order number. The model only reads what the customer wrote; prices, stock and totals are written by code from the stock file, and «پشت صحنه» shows which file each answer came from. An order goes into `web_orders` and the sales file's «سفارش‌های سایت» sheet as «پرداخت نشده», is logged, and owner and seller get a toast and a badge (`webOrders.js`). Once paid, «پرداخت شد، فاکتور بزن» makes a normal invoice through `api.make_invoice` (a new customer is added to the accounts file first). Website orders are not invoices, so they do not touch stock or the reconciliation until then.
- The live site resets it with the school (`RESET_ON_LOAD`). Locally the assistants page only shows with `HUB=1`; without it the school opens straight away, so the school's e2e tests are unchanged. `tests/test_fabric.py` covers it.

## Rules that must not break

- Words on screen are plain everyday Persian that any parent, teacher or manager understands at once. No office jargon (no «ارجاع», «رؤیت», «صدور», «در دست اقدام», «اعلام وصول»): say «فرستادن», «دیدن», «در حال انجام», «تأیید دریافت». Official letter texts the model writes keep their formal tone.
- On phones, check every new list at 360px: no text squeezed beside a tag or running into another line.
- Dropdowns get their arrow from `main.css` (12px in from the edge); don't put back the browser's own.

- Role and identity come from the logged-in user (`require_role`, `user["ref_id"]`), never from the request body or the question.
- Numbers are computed by code; the model only writes text. Model output that contains numbers is checked against the computed facts (stats replies, warning dates, parent answers).
- Human in the loop for anything that leaves the office or is a decision.
- Parents see only their own child. Counselor notes, health-form flags and unapproved suggestions never reach parents or the model in parent flows. No comparison with other students.
- Vector search always filters by `access_{role}`.
- SQLite allows one writer: send notifications after the write transaction commits.
- Never write a school, manager or counselor name into code, prompts or seed data: take it from `school.py` (backend) or `schoolInfo` (frontend).
- Any new model-written text shown to a parent goes through `checks.unsafe_for_parent` and `checks.only_known_numbers`, with a code-built fallback.
- Don't commit `.env`, `school.db`, `db/` or model files.
- Run tests only when Hassan asks. Don't run the full suite (`pytest` plus `pnpm test:e2e`) on every change or before merging: it takes his time. When a change needs a check, run only the tests for that part (e.g. `pytest -k manager`).
